# SEO-аудит DOVIRA — 20.09.2026

Перевірено локальний код і HTTP-відповіді https://mydovira.com. Доступу до Google Search Console немає. Кількість URL у sitemap нижче **не є кількістю сторінок в індексі Google**. Даних для висновку про санкції Google або точну причину низького трафіку недостатньо. Коментарі в наявному коді про «демоцію серпня» не є доказом санкцій.

## Головний висновок: змішані дані різних бізнесів

На публічних сторінках підтверджено не лише невідповідність slug і назви, а й суперечності між назвою, описом, категорією, послугами та відгуками:

| Сторінка | Публічний вміст під час перевірки |
| --- | --- |
| [advokatske-biuro-avgustinov-om](https://mydovira.com/profiles/advokatske-biuro-avgustinov-om) | Title і назва — «Eurokonus, інтернет-магазин сантехніки». Опис, послуга «адвокат», AI-аналіз та видимі відгуки — про адвокатське бюро Августінова. |
| [pantera-perukarnia](https://mydovira.com/profiles/pantera-perukarnia) | Назва — «Айсбан, ресторан». Категорія — «Ветеринари та ветеринарні клініки». Є стоматологічні та будівельні послуги; AI-аналіз — про «Олтан-вет» у Рівному. |
| [Будівельні магазини](https://mydovira.com/catalog/budivelni-magazini) | Серед посилань на профілі у поточній видачі є `/profiles/vikonda-kafe`. Потрібна перевірка рубрик і джерел імпорту. |

Перші дві сторінки повертають HTTP 200, `index, follow` і canonical на власний URL. Пошуковик може отримувати всі ці суперечливі дані як вміст однієї сутності. Це підтверджений дефект даних; його вплив на конкретні позиції без GSC не виміряний.

### Що перевірити перед виправленням даних

1. Зіставити профілі з історією імпортів, резервною копією, `profile_data_sources`, початковими назвами та URL джерел.
2. Перевірити відповідність саме бізнесу: назва, адреса, телефон, категорія, послуги, відгуки, досьє, AI-аналіз. Не визначати правильну назву лише зі slug.
3. Окремо перевірити `Top20BulkImportService::findExistingProfile()` і `fillProfileFromImport()`: зіставлення за сайтом/телефоном може повернути наявний профіль, а імпортована назва записується навіть без overwrite. Це ризик у коді, **не доведена історична причина** цих прикладів.
4. Після встановлення джерела змішування підготувати перелік конкретних виправлень і резервну копію. Не запускати масове перейменування або `--fix` на основі припущень.

Наявна команда `php artisan dovira:audit-catalog-data --visible` працює в dry-run без `--fix` і може допомогти знайти конфлікти рубрик. Вона не перевіряє повну тотожність бізнесу й не замінює звірку відгуків із джерелами. Під час цього аудиту команда на продакшені не запускалася, дані не змінювалися.

## Технічна перевірка

| Перевірка | Результат |
| --- | --- |
| Головна, `/catalog`, `/catalog/advokaty/kyiv` | HTTP 200, індексація дозволена, HTTPS canonical |
| `/robots.txt` | HTTP 200; публічні профілі й каталог не заборонені; є посилання на sitemap |
| `/sitemap.xml` | HTTP 200; sitemap-index із трьома дочірніми файлами |
| `/sitemap-static.xml` | 21 URL |
| `/sitemap-landing.xml` | 2 321 URL |
| `/sitemap-profiles-1.xml` | 3 717 URL |
| Вигаданий URL | HTTP 404, не soft-404 із кодом 200 |
| `/catalog?q=дрім` | HTTP 200, **index, follow**, canonical на загальний каталог — локально виправлено |

Запити з типовим Python User-Agent отримували 403; повторна перевірка з браузерним User-Agent повертала 200/404. Це не доводить блокування Googlebot. Його доступ перевіряється live URL Inspection у GSC і журналами Cloudflare/сервера.

### Локально виправлено, ще не розгорнуто

- Внутрішній пошук, фільтри, альтернативне сортування та сторінки 2+ загального каталогу отримують `noindex, follow`, як і фільтровані посадкові. Чистий каталог і tracking-параметри залишаються indexable.
- Кеш готового sitemap XML та списків URL перевіряє поточний режим `SEO_STRICT_PROFILE_INDEXING` і поріг `SEO_STRICT_MIN_DESCRIPTION`. Раніше готовий XML міг лишатися від попередньої політики до шести годин, хоча кеш списку профілів частково враховував strict-режим. Простір ключів змінено на v3 для нового формату кешу.
- Додано HTTP-регресії для пошуку/фільтрів і перемикання політики індексації після прогрівання sitemap.

Ці зміни не виправляють змішані дані профілів і не гарантують зростання трафіку. Прапорець strict на сервері не перемикався; масове відкриття/закриття сторінок не виконувалося.

Перевірка: `SeoIndexingRegressionTest` — 13 тестів / 40 перевірок; `ProfileSeoTest` — 8 тестів. У `CatalogSearchTest` залишаються два наявні збої: fallback-зображення та пошук слів імені в довільному порядку. Обидва відтворено також із тимчасовою копією контролера без нового SEO-блоку; робочі файли для цього не відкочувалися. Pint для зміненого кешу й нових тестів, PHP syntax check контролера та diff whitespace check пройшли.

## Запит «жк дрим хиллс» і 300 за тиждень

На обрізаному скриншоті видно лише один рядок, 0 і 1, без заголовків колонок. Якщо це стандартні кліки й покази GSC, це **0 кліків та 1 показ**, а не відвідування за цим запитом. Один такий рядок не характеризує всю семантику сайту.

Точна посадкова для цього запиту не встановлена. DOVIRA має профілі нерухомості/забудовників, тому сама по собі поява запиту про ЖК не доводить помилку. Треба відкрити цей запит у GSC → «Сторінки» і подивитися URL, позицію та кількість показів.

Для наступного висновку потрібні:

- Уточнення: 300 — покази, кліки чи відвідування; дата запуску сайту.
- GSC → «Ефективність», останні 3 місяці: експорт запитів і сторінок із кліками, показами, CTR та середньою позицією; порівняння періодів.
- GSC → «Індексування сторінок»: кількість індексованих і причини виключення.
- GSC → перевірка кількох цільових URL: останній crawl, canonical Google, доступність індексації.
- Перевірка розділів ручних заходів і безпеки — для підтвердження/спростування санкцій, а не припущень про них.

Пріоритет: відновити узгоджені дані профілів → розгорнути технічні виправлення → перевірити GSC → покращувати конкретні цільові сторінки за реальними запитами. Генерувати ще більше сторінок до виправлення даних недоцільно.

Офіційні джерела: [noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing), [sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [корисний і достовірний контент](https://developers.google.com/search/docs/fundamentals/creating-helpful-content). Sitemap допомагає виявленню URL, але не гарантує індексації або позицій.
