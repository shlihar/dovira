# PRO Account Page Guidelines

Цей файл треба прочитати перед будь-якою роботою зі сторінкою PRO-кабінету DOVIRA.

Основна сторінка: `resources/views/pro/account.blade.php`.
Основні стилі: `public/static/css/pages/pro-account.css`.
Контролер: `app/Http/Controllers/ProAccountController.php`.
Feature-тести: `tests/Feature/ProAccountTest.php`.

## Загальний принцип

PRO-кабінет має виглядати як єдина SaaS-панель керування профілем, а не як набір різних сторінок. Нові вкладки і блоки робити через уже існуючі класи та структури, якщо це можливо.

Не створювати нову візуальну систему для кожної вкладки. Якщо блок схожий на вже готовий блок у `Огляд`, `Профіль` або sidebar, треба перевикористати існуючу структуру або винести спільний partial.

Текст, відступи, висота інпутів, селекти, кнопки, бейджі, списки і картки мають бути в тих самих розмірах, що вже використовуються на вкладках `Огляд` і `Профіль`.

## Що не чіпати без окремого прохання

Sidebar уже вважається готовим. Не змінювати його структуру, навігацію, ширину, загальні відступи і базовий стиль без прямого запиту.

Якщо треба додати картку в sidebar, використовувати shared partial:

`resources/views/pro/partials/sidebar-status-card.blade.php`

Ця картка є базою для `Ваш PRO-статус`, `Заповнення профілю` та майбутніх sidebar-карток. Міняти треба дані, іконки, top block, кнопку, але не дублювати окрему нову картку вручну.

## Спільні компоненти

### Sidebar status card

Використовувати для sidebar-карток:

`@include('pro.partials.sidebar-status-card', [...])`

Підтримує:
- `title`
- `badge`
- `topBlock`
- `items`
- `action`
- `cardClass`
- `id`

Список повинен використовувати ті самі класи:
- `pro-account-sidebar-status__list`
- `pro-account-sidebar-status__list-icon`
- `pro-account-sidebar-status__list-label`

Не робити окремий список з іншими розмірами іконок чи тексту.

### Completion card

Для великої картки заповнення на вкладці `Огляд` є partial:

`resources/views/pro/partials/completion-card.blade.php`

Використовувати його тільки там, де потрібна саме overview-style completion card. Для sidebar completion використовувати `sidebar-status-card`.

## Вкладка Огляд

Вкладка `Огляд` є головним джерелом готових класів для:
- заголовків карток;
- метрик;
- графіків;
- компактних review-card;
- completion-card;
- кнопок;
- бейджів;
- загальної щільності інтерфейсу.

Перед додаванням нового блоку на інші вкладки треба перевіряти, чи вже є схожий блок у `Огляд`.

## Вкладка Профіль

Профіль редагується через компактні поля, які виглядають як сучасні SaaS input/select/textarea.

Основні правила:
- поля мають бути одразу в режимі вводу, без зайвої кнопки `Зберегти`;
- збереження відбувається AJAX-ом після blur/change;
- зверху показується короткий toast, а не великий alert-блок;
- інпути і селекти мають однаковий розмір тексту;
- селекти мають стрілку і таку саму висоту, як інпути;
- короткий і розгорнутий опис мають висоту по контенту, але на один рядок більшу;
- форма не повинна скакати при фокусі чи редагуванні.

Для телефону використовується маска через готову бібліотеку IMask:

`public/static/vendor/imask.min.js`

### Послуги

Логіка послуг:
- користувач сам вводить послуги;
- під час вводу показуються підказки з уже існуючих послуг;
- можна вибрати існуючу або створити нову;
- не показувати користувачу весь список послуг сайту одразу;
- додавання/видалення має бути плавним;
- поле вводу не має виглядати як окремий великий незручний input всередині chip-зони.

### Соцмережі

Логіка соцмереж:
- додані соцмережі показуються як інпути у 2 колонки;
- нижче показуються іконки ще не доданих соцмереж;
- користувач натискає іконку, і з'являється відповідний input;
- після додавання соцмережі її іконка з доступних зникає;
- іконки соцмереж мають бути в кольорі відповідної соцмережі;
- соцмережі не мають відкриватися через загальну кнопку `Редагувати`.

Підтримувані популярні мережі: Telegram, Facebook, Instagram, YouTube, Viber, WhatsApp.

### Медіа

Медіа має виглядати як картки:
- обкладинка;
- логотип;
- фото галереї;
- картка `Додати фото`.

Клік по `Додати фото` має відкривати системний file picker через прихований file input, як на сучасних платформах.

Файли зберігаються у public disk за структурою:

`storage/app/public/profiles/{profile_id}/gallery`

Це правильний напрям для масштабу проекту: профільні файли ізольовані по `profile_id`, URL віддаються через public storage, старі файли видаляються при видаленні з галереї.

## Вкладка Відгуки

Сайдбар на цій вкладці не змінювати.

Вкладка `Відгуки` має будуватись як робочий простір:
- зверху заголовок і короткий опис;
- summary-картки;
- пошук;
- сортування;
- фільтри;
- список відгуків зліва;
- активний відгук справа;
- відповідь на відгук пишеться в правій панелі;
- дії `відповісти`, `сховати`, `показати` мають бути логічно прив'язані до активного відгуку.

Поточний partial правої панелі:

`resources/views/pro/partials/review-detail-panel.blade.php`

Логіка вкладки:
- клік по review-card відкриває відгук справа без перезавантаження;
- форми відповіді і приховування залишаються звичайними Laravel POST/PATCH;
- пошук і фільтри працюють клієнтським JS по поточному набору;
- шаблони відповіді підставляють текст у textarea;
- лічильник символів відповіді оновлюється під час вводу.

Не повертатися до старої логіки, де textarea відповіді стоїть під кожним відгуком у списку.

## SEO для профілів

SEO генерується не заглушками, а через:

`app/Support/ProfileSeo.php`

Платформа DOVIRA є платформою відгуків, тому головний SEO-фокус:

`Відгуки про {профіль}`

Title і description мають починатися з відгуків про профіль, а категорія, місто, послуги і контакти мають бути підтримкою, не головною темою.

Приклад напряму:

`Відгуки про Nova QA 72018в, адвоката в Одесі. Адвокатські послуги, індивідуальна адвокатська діяльність, адміністративне право. Контакти на DOVIRA.`

Не вставляти в SEO тестові або службові фрази типу `для перевірки збереження`.

## AJAX-збереження профілю

Форма профілю зберігається через AJAX у `account.blade.php`.

Важливі правила:
- не додавати окрему кнопку `Зберегти` для кожного поля;
- blur/change запускає збереження;
- поточне поле зберігається без перезапису інших незбережених dirty-полів;
- після відповіді сервера SEO-поля синхронізуються з payload;
- toast показує короткий статус.

## Візуальні правила

Використовувати існуючі кольори та класи з:

`public/static/css/pages/pro-account.css`

Не робити:
- великі нові шрифти, які вибиваються з вкладок;
- різні розміри тексту для однакових полів;
- нові картки, якщо вже є аналог;
- nested cards;
- різні стилі списків для sidebar-карток;
- кнопки там, де на референсі і в поточній логіці має бути inline/instant action.

Для нових блоків перевіряти:
- чи схожий блок є в `Огляд`;
- чи схожий блок є в `Профіль`;
- чи можна використати existing partial;
- чи список/іконки/кнопки мають той самий розмір.

## Перевірка після змін

Для Blade/CSS змін мінімум:

```bash
php artisan view:cache
```

Якщо зачеплено контролер, форми, AJAX, відгуки, SEO або збереження:

```bash
php artisan test --filter=ProAccountTest
```

Для зміни відображення бажано перевіряти сторінку скріншотом у браузері, особливо вкладки:
- `Огляд`
- `Профіль`
- `Відгуки`

## Як починати новий чат

У новому чаті сказати:

`Прочитай docs/pro-account-guidelines.md і працюй по цих правилах.`

Після цього треба прочитати цей файл перед змінами у PRO-кабінеті.
