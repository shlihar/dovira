# Застосовані SEO-виправлення — 21.09.2026

## На сервері

1. Виправлено помилковий noindex на канонічних підкатегоріях: параметр `sub`, який додає сам маршрутизатор, більше не вважається користувацьким фільтром. Справжні query-фільтри, пошук, інше сортування, legacy tab та пагінація залишаються noindex.
2. Статистика й SEO-вміст категорій враховують тільки активні, опубліковані та видимі в каталозі профілі.
3. Sitemap рахує унікальні профілі: прив'язка однієї компанії і до батьківської, і до дочірньої категорії не збільшує кількість компаній. Після виправлення з sitemap вилучено три недостатньо заповнені посадкові.
4. Нативний відгук відкриває профіль лише після публікації. Pending/hidden не є публічним SEO-контентом.
5. Додано явний список `seo.reviewed_profile_ids` для вибіркового відкриття перевірених профілів, незалежно від порогу довжини опису. Зміна цього списку оновлює кеш sitemap. Список поки порожній: автоматично відкритих кандидатів немає.
6. Прибрано непідтверджені твердження про санкції Google з коментарів політики. Strict-режим лишився ввімкненим.

Розгорнуто шість файлів точково, із перевіркою попередніх контрольних сум і резервними копіями. Зміни інших задач не розгорталися. Копії: `/home/nu625309/dovira-seo-fix-RQ31q5PY/backup/`. Результат `config:cache` — успішний. Нові версії кешів посадкових і sitemap усувають старі результати.

## Перевірки

- 33 тести, 110 перевірок: `CatalogLandingIndexingTest` та `SeoIndexingRegressionTest` — успішно.
- На production перевірено SQL-умови наповненості для всіх **491 категорійних URL** sitemap — розбіжностей немає.
- Виправлення стосується **307 URL підкатегорій**. Попередня оцінка 419 включала 112 національних сторінок послуг, які мають таку саму кількість сегментів URL; їх індексацію ця помилка не блокувала. Уточнений склад sitemap: 491 категорійна + 112 національних послуг + 1 713 послуг у містах = **2 316 посадкових URL**.
- 12 зовнішніх HTTP-перевірок підтвердили правильні index/noindex та HTTP 200. Зокрема, адвокати/Київ, стоматології/Київ, ресторани/Львів і загальна категорія адвокатів тепер `index`.
- Масовий HTTP-обхід зупинено після rate limit 429 для адреси аудитора; його результати не видаються за перевірку всіх URL. Після відновлення ліміту виконано контрольні запити з паузами. Всі 491 URL перевірені серверним запитом щодо придатності, а не повним HTTP-обходом.

Докази: `seo-fix-http-verification.json`, `seo-fix-eligibility-verification.json`, `seo-fix-summary.json`, `seo-fix-deployment-receipt.txt`.

## Що зробити власнику сайту зараз

1. У Search Console → «Файлы Sitemap» перевірити поданий `https://mydovira.com/sitemap.xml`; якщо відсутній — додати, якщо вже є — можна повторно подати один раз. Не видаляти ресурс чи історію.
2. У «Проверка URL» вставити по черзі:
   - `https://mydovira.com/catalog/advokaty/kyiv`
   - `https://mydovira.com/catalog/stomatologiyi/kyiv`
   - `https://mydovira.com/catalog/restorani/lviv`
   Виконати «Проверить опубликованную страницу»; якщо індексацію дозволено, натиснути «Запросить индексирование». Старий статус у збереженій перевірці може не змінитися відразу. Не запускати глобальне підтвердження виправлення всіх noindex: багато з них залишаються навмисними.
3. Експортувати «Эффективность → Результаты поиска» за останні 3 місяці: увімкнути кліки, покази, CTR і середню позицію; тип пошуку «Веб», без фільтра окремої сторінки/запиту. Передати архів експорту з таблицями сторінок і запитів. Додатково передати таблицю причин неіндексації та перевірити розділ ручних заходів: без цих даних причину низьких показів остаточно не встановлено.
4. Почати з кількох бізнесів, із якими вже є контакт: запропонувати добровільно підтвердити/уточнити картку й запросити справжніх клієнтів залишити чесний відгук. Не вимагати позитивної оцінки й не створювати штучні відгуки. Автоматичних розсилок у цій роботі не було.
5. Зафіксувати дату 21.09.2026. Перевіряти раз на тиждень нові проіндексовані категорійні URL, небрендові запити, покази та кліки. Через 28 днів порівняти з попередніми 28 днями, враховуючи зміни попиту. Період 4–6 тижнів — для спостереження, не гарантія результату.

Google рекомендує sitemap для багатьох URL, URL Inspection — для окремих. Повторення запитів індексації не прискорює обхід; навіть успішний live test не гарантує включення в пошук: https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl

## Що ще потребує даних/перевірки

2 902 профілі з попереднього аналізу є кандидатами, не підтвердженою групою для відкриття. Список `growth-candidates.json` готовий. Відсутність евристичних прапорців не доводить точність контактів, належність відгуків чи оригінальність опису. Перед додаванням ID у конфіг потрібен датований запис перевірки: джерело компанії, місто/категорія, відповідність опису й відгуків, відсутність дубля, конкретна користь сторінки. Після редагування конфігу виконати `config:cache`, перевірити HTML і sitemap; статус публікації все одно обмежує доступність профілю.

31 пошкоджений профіль залишаються чернетками зі збереженими даними й резервними копіями. Історичне розділення їхніх відгуків не завершене; потрібні підтверджені джерела або початкові імпортні файли. Деталі в `repair-2026-09-21.md`.

Ці зміни усувають перевірені технічні перешкоди. Фактичний індекс Google, попит і позиції потрібно оцінювати за Search Console; 19,4 тис. у попередньому скриншоті не замінюються кількістю URL у sitemap.
