# Повторна перевірка SEO після відкриття публічних профілів

Дата: 22.09.2026. Аудит бойового mydovira.com, без змін сайту чи даних у цьому проході.

## Виправлення за наступним запитом власника — 23.09.2026

Розгорнуто `public/.htaccess` та `app/Http/Controllers/SeoController.php`.

- Завершальний слеш на бойовому домені: прямий 301 на HTTPS без слеша, query-параметри збережені. Підтверджено зовнішнім HTTP-запитом.
- Ненадійний optional lastmod прибрано з URL профілів і запису їхнього файла в sitemap-index. Старі updated_at не видаються за дату редагування контенту. Статистика й її поточний механізм інвалідації кешу не змінювалися; оптимізація частоти перегенерації — окреме покращення продуктивності.
- Старий `/sitemap-ratings.xml`: 301 на `/sitemap-landing.xml`, що містить canonical-адреси каталогу. Ціль повертає 200 і валідний XML з 2 316 URL.
- Після очищення кешу профільний sitemap: 34 226 URL, валідний XML, без lastmod. Серверний режим all_public збережений. Перевірений раніше закритий профіль повертає 200/index, карантинний — 404/noindex.
- 27 цільових тестів / 134 твердження пройшли (ProfileContentIndexingTest і sitemap-тести SeoIndexingRegressionTest). Перевірено PHP-синтаксис і diff whitespace.
- Перед розгортанням збіг серверних файлів із локальною базовою версією перевірено SHA-256; резервна копія: `/home/nu625309/dovira-seo-three-fixes-7tl49N/`.

## Обсяг і результати

- Серверний режим: `all_public`; APP_URL: `https://mydovira.com`.
- Повна звірка множин URL: 34 226 публічних профілів у БД = 34 226 у sitemap. Пропущених і зайвих URL немає; карантин виключений.
- Основний sitemap-index та три дочірні файли доступні, XML валідний.
- Статичні сторінки: 21 URL / 3 586 байтів; посадкові: 2 316 / 370 497; профілі: 34 226 / 7 037 632. Разом 36 563 URL, дублів усередині й між файлами немає. Ліміти 50 000 URL / 50 MB на файл не перевищені.
- Дати lastmod синтаксично коректні, майбутніх дат не виявлено. Семантична точність дат має проблему нижче.
- 58 HTML-сторінок із sitemap перевірено по HTTP: усі 200, index/follow, один self-canonical, title, description і H1; JSON-LD парситься без помилок. Це перевірка синтаксису, не сертифікація всіх типів structured data.
- HTTP та www перенаправляють 301 на HTTPS без www.
- Tracking URL профілю має canonical на чистий URL і залишається indexable.
- Пошук (з коректним percent-encoding), сортування й сторінка 2 каталогу: noindex/follow; поза sitemap. Це не заборона індексації самих профілів.
- Неіснуючий та контрольний карантинний профілі: справжні 404. Неіснуюча друга частина sitemap профілів: 404 і не зазначена в індексі.
- robots.txt не блокує /profiles/ і містить посилання на основний sitemap.
- Запити з User-Agent Googlebot до sitemap і контрольного профілю отримали 200. Імітація User-Agent не підтверджує доступ із реальної мережі Google.

## Знайдені недоліки

1. Редирект завершального слеша погіршує схему: `https://mydovira.com/profiles/stomat-alians-stomatologicnii-centr/` -> 301 `http://mydovira.com/profiles/stomat-alians-stomatologicnii-centr` -> 301 HTTPS. Потрібний прямий 301 HTTPS -> HTTPS. У sitemap використано чисті URL, тому його адреси цим ланцюжком не проходять. Джерело для виправлення: public/.htaccess, правило завершального слеша.
2. Sitemap бере lastmod із profiles.updated_at. Лічильники переглядів/кліків оновлюють модель через increment, а ProfileObserver також скидає sitemap на змінах цих лічильників. Потрібно відокремити дату зміни контенту й інвалідацію sitemap від статистики. Це не noindex, але сигнал оновлення неточний і генерація кешу може бути зайвою.
3. `/sitemap-ratings.xml` усе ще повертає URL `/top/*`, canonical яких вказує на `/catalog/*`. Основний sitemap-index правильно НЕ посилається на ratings. Варто перевірити, чи старий файл окремо поданий у GSC, та прибрати суперечність у його призначенні/вмісті. Рішення про окрему індексацію рейтингів потребує визначеної SEO-стратегії, а не автоматичної зміни canonical.

## Межі висновку

Повністю перевірені XML і відповідність списку профілів базі. HTTP та HTML перевірені вибірково (58 сторінок із sitemap плюс діагностичні варіанти, близько 70 адрес), а не всі 36 563 сторінки. Не перевірено актуальний статус Google URL Inspection, обрані Google canonical, ручні заходи, доступ із реальних IP Googlebot, Core Web Vitals чи повну достовірність контенту всіх профілів. Відсутність масового noindex не гарантує повернення позицій.

Діагностичний скрипт: tmp/seo-recheck-2026-09-22.php. Початковий прогін мав дві особливості самої перевірки: коренева адреса без завершального / помилково позначалася як форматна помилка (це валідний URL), а необроблена кирилиця в query давала 400. Обидві виправлено у скрипті; пошук із percent-encoding окремо повторно перевірено й отримано HTTP 200/noindex/follow.

Джерела: https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap і https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls .
